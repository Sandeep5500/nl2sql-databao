# Synthesized judge-training data

Training items for the pairwise judge (see `documents/judge_finetuning_plan.md`).
One JSONL record per item. **Tracked in git** — unlike `logs/`, this is a durable
artifact that has to be reproducible and shareable, not a log.

Generated by `nl2sql-v2/scripts/synth_questions.py` in three stages: a strong
model writes gold SQL from a failure-mode template, the same model phrases a
question for it, and a **different** model states the expected output shape blind
to the gold SQL as an ambiguity gate.

## Leakage rule

The 135 `local*` Spider 2.0 instances are our test set. Nothing here touches
them:

- **Schemas** are foreign (a locally generated bike-share database here; SynSQL
  databases for the real run). Never one of the 30 Spider 2.0 local databases.
- **Questions and gold SQL** are newly written, so the mapping cannot be
  memorized whatever is in a model's pretraining.
- **Style exemplars** come only from the ~412 *non-local* `spider2-lite`
  instances — same authors and register, different databases.
  `load_exemplars()` skips every `local*` instance unconditionally, and the
  printed banner states how many exemplars loaded and that 0 came from the
  test set.

## Files

| file | items | what changed |
|---|---|---|
| `pilot10_v1_noexemplars.jsonl` | 10 | First pilot. No style exemplars, no diversity forcing. **4 of 10 show `gated_out` but were JSON truncation** (gate `max_tokens` was 800, too small for a 12-column enumeration) — not real rejections. |
| `pilot10_v2_exemplars.jsonl` | 10 | Adds Spider 2.0 exemplars, the metric-vs-mechanism ban list, forced focus tables and measure. Focus tables sampled at random, which made one incoherent item (`syn0008`, unrelated tables joined for no reason). Exemplars filtered 30–140 words, biasing questions long (94-word median). |
| `pilot10_v3_connected.jsonl` | 10 | Focus tables are a connected subgraph walked along foreign keys. Exemplar pool narrowed to 30–75 words (median 50, matching the benchmark). One genuine gate rejection (`syn0006`: "busiest" undefined). |

Measured across the three:

| | v1 | v2 | v3 |
|---|---|---|---|
| questions with a SQL mechanism tell | 6/10 | 0/10 | 1/10 (a false positive) |
| median question length (words) | 76 | 94 | 76 |
| max pairwise column overlap | 80% | 29% | **14%** |
| gate passes that committed to a row count | 4 | 4 | 5 |

Spider 2.0 non-local reference: median 50 words. Residual length is mostly
structural — question length correlates with column count at r = 0.90, because
an 11-column enumeration has to name 11 things.

## Record fields

| field | meaning |
|---|---|
| `id` | `synNNNN`, unique within a file |
| `bucket` | failure-mode template: `multi_clause`, `set_then_aggregate`, `enumerated_columns`, `boundary`, `fanout`, `metric_definition` |
| `focus_tables` | the connected table set the query was told to centre on |
| `measure` | the forced headline measure kind |
| `gold_sql` | correct **by construction** — it executed and returned rows |
| `gold_rows`, `gold_cols`, `gold_columns` | the gold result's actual shape |
| `gold_preview` | first 15 rows, CSV |
| `question` | the natural-language question |
| `gate` | the blind validator's reading: `rows`, `row_grain`, `columns`, `ambiguous`, `why` |
| `gate_rows_ok`, `gate_cols_ok`, `gate_committed` | gate agreement; `gate_committed` is false when it answered `rows: null` and so passed on column count alone |
| `status` | `pass`, `gated_out`, or `sql_failed` |
| `provenance` | see below |

## Provenance and reproducibility

The database is **not stored** — the generator script plus its seed is a smaller
and more honest artifact. Every record carries:

```
provenance.db_note        how to rebuild the database
provenance.db_sha256      hash of the database file it was written against
provenance.schema_sha256  hash of the schema DDL
provenance.synth_seed     --seed for the synthesis RNG
provenance.model          model for gold SQL + question
provenance.gate_model     model for the blind gate
provenance.exemplar_file  question file the style exemplars came from
provenance.git_commit     repo state at generation time
```

Verified for these files:

```bash
uv run python nl2sql-v2/scripts/make_synth_db.py --out /tmp/verify.sqlite --seed 7
# -> db_sha256 and schema_sha256 both match the recorded values byte for byte
```

For the real run, set `--db-note` to the SynSQL database identifier so the same
check works there.

## Regenerating

```bash
cd nl2sql-v2
uv run python scripts/make_synth_db.py --out /tmp/bikeshare.sqlite --seed 7

OPENAI_API_KEY=sk-... uv run python scripts/synth_questions.py \
  --db /tmp/bikeshare.sqlite --n 10 --seed 2 \
  --db-note 'nl2sql-v2/scripts/make_synth_db.py --seed 7' \
  --base-url https://ai-gateway.andrew.cmu.edu/v1 --model gpt-5.4 \
  --gate-base-url https://ai-gateway.andrew.cmu.edu/v1 \
  --gate-model gemini/gemini-3.5-flash \
  --out ../data/synth/pilot10_v3_connected.jsonl
```

The key is a CMU AI Gateway virtual key (`https://ai-gateway.andrew.cmu.edu/ui`
→ Virtual Keys). It is a LiteLLM proxy, so model names are the gateway's
aliases; `gpt-5.4`, `gemini/gemini-3.5-flash` and the Claude models are all
available. Gold SQL and question generation share one strong model; the gate must
be a **different** model, or its agreement is self-confirming.

Note the gateway hostname is CMU-internal — it does not resolve off the VPN.
